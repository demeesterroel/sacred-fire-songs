## Overview

Seven targeted fixes to polish the mobile experience after the initial 1.1.9 implementation. Focus is on consistency, reduced clutter, and natural mobile interactions.

---

## 1. Consistent Header Titles

**Problem:** Page titles in the global header are inconsistent across routes and subpages.

**Design:** Establish a definitive title mapping in `Header.tsx`:

| Route | Title |
|-------|-------|
| `/` | Dashboard |
| `/songs` | Songs *(or "{count} songs" when filtered)* |
| `/songs/add` | Add Song |
| `/songs/[id]` | *(header hidden — custom layout)* |
| `/songs/[id]/edit` | Edit Song |
| `/explore` | Explore |
| `/library/playlists` | Your Library |
| `/library/playlists/add` | New Playlist |
| `/library/playlists/[id]` | *(playlist name via dynamic title)* |
| `/account/settings` | Settings |

For dynamic titles (e.g., playlist name), use the existing `SidebarContext.dynamicTitle` pattern.

## 2. Context-Aware Create (+) Button

**Problem:** The bottom nav "Create" tab always hard-navigates to `/songs/add`.

**Design:** Replace the direct link with a **bottom sheet** triggered on tap.

**Sheet contents (2 rows max):**
- **On Songs pages:** primary "Add Song", secondary "Create Playlist"
- **On Library / Playlist pages:** primary "Create Playlist", secondary "Add Song"
- **On any other page:** "Add Song" + "Create Playlist"

The primary option (top row) matches the current context. Each row is an icon + label, tappable.

**Implementation:**
- Small portal component with Tailwind slide-up transition.
- Tap outside or swipe down to dismiss.
- Bottom nav "Create" icon becomes a `<button>` instead of a `<Link>`.
- No external library needed.

## 3. Simplified Add Song Form

**Problem:** Nested collapsible sections create visual heaviness — too many boxed sections within sections.

**Design — Form field priority order:**

1. **Title** — required, top of form (simple input)
2. **Author** — optional but prominent, directly below title (simple input, not inside a collapsible)
3. **Lyrics & Chords editor** — the core content, immediately after author
4. **Key / Capo / Tuning** — optional, collapsed by default, low priority. Flatten into inline inputs (no card-within-card styling).
5. **Categories / Tags** — optional, collapsed by default
6. **Links** (YouTube, Spotify, Soundcloud) — optional, collapsed by default
7. **Melody Notation** — collapsed by default, **disabled** with a `[Coming Soon]` badge on the section header. Textarea hidden behind a non-functional toggle.
8. **File Upload** — toggle, stays as-is

**Visual changes:**
- Remove inner card/border styling on collapsible sections. Use simple dividers or spacing instead.
- Reduce vertical spacing between form groups.
- The top of the form reads as: `Title → Author → Editor` — the user can start writing immediately without scrolling past metadata.

## 4. Song Detail Header Cleanup

**Problem:** Mobile header is cluttered with too many action buttons and the avatar menu still appears.

**Design — Mobile song detail header:**

```
[← Back]        Song Title        [♡]  [⋯]    (authenticated)
[← Back]        Song Title        [♡]          (guest)
```

- **Left:** Back arrow → navigates to previous page.
- **Center:** Song title, truncated with ellipsis.
- **Right (guest):** Favorite heart button only — always visible, triggers sign-up nudge for guests.
- **Right (authenticated):** Favorite heart + overflow menu (`⋯`). Overflow contains: Edit, Add to Playlist, Delete.
- **No avatar/user profile** on the song detail header — ever, for any user type.

## 5. Sidebar Menu Visual Cleanup

**Problem:** General and Personal nav sections aren't visually separated cleanly, and the user identity card is a separate block mid-sidebar.

**Design:**

**Mobile sidebar header (replaces logo for auth users):**
```
[Avatar]  Name          [✕ Close]
          Role badge
```

- When a user is signed in, the sidebar header shows their avatar, name, and role instead of the flame logo.
- Guest users keep the flame logo + "Sacred Fire Songs" title.
- The separate user identity card further down in the sidebar is **removed** — no duplication.

**Section labels:**
- Add subtle section headers: `MENU` above nav items, `PERSONAL` above personal actions.
- Style: small uppercase text, `text-xs text-gray-500 tracking-wider`, with padding.

**Spacing:**
- Increase padding above/below the `border-t` separator between sections.

## 6. Swipe Between Tabs

**Design:** Horizontal swipe gesture triggers a full page transition between bottom nav tabs.

**Tab order:** `["/", "/songs", "/library/playlists"]`
- Swipe left → next tab
- Swipe right → previous tab

**Implementation:**
- `useSwipeNavigation` hook listening for `touchstart` / `touchmove` / `touchend` on the main content area.
- Threshold: >50px horizontal, <30px vertical (avoids scroll conflicts).
- On trigger: `router.push()` with a CSS `translate-x` slide animation (200ms).

**Exclusions:**
- Do NOT enable swipe on create pages (`/songs/add`, `/library/playlists/add`).
- Do NOT capture swipe when the touch target is inside a `.hide-scroll` container (protects dashboard carousels).
- Wrap at edges (no swipe right on Home, no swipe left on Library).

---

## 7. Sidebar Push (Not Overlay)

**Problem:** Current sidebar overlays/hovers over content. User wants it to push content aside.

**Design:** When the sidebar opens on mobile, the main content area slides right.

- Sidebar opens → main content translates right by 260px (sidebar width).
- Smooth transition: 300ms ease-in-out on both sidebar and content.
- No dark backdrop overlay.
- Tapping on the pushed content area closes the sidebar.
- On desktop (`lg:+`): sidebar remains a permanent sticky sidebar — no change.
